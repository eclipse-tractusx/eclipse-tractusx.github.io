Community Office Hour 2026-11-13

November 13, 2026
Tom Meyer
PURIS Architect, Eclipse Committer
Stephan Bauer
Eclipse Tractus-X Project Lead

Community Office Hour Meeting Minutes​

Status updates discussed in meeting:

Executive Summary​

  • The website build-strategy and GitHub Actions rework are complete. The reported limit of five to six concurrent pull-request previews remains unresolved and will be tracked separately.
  • The tractusx-starter-kit has completed its initial governance setup and held its first open meeting. Further contributors are welcome.
  • The release-management workshop is being prepared as a cross-initiative Tractus-X activity, not a Catena-X-only workshop. Timing depends on stakeholder identification and availability.
  • Secret-scanning performance, outdated documentation, component-maintenance responsibilities, and AI contribution guidance remain open.

Topics Discussed​

Community Days and Outreach​

  • The seventh Tractus-X Community Days in Stuttgart were promoted as an opportunity for in-person collaboration, workshops, and business and technical discussions.
  • Workshop details were not yet published at the time of the meeting.
  • Participants were encouraged to share the event and support promotion through the Tractus-X LinkedIn page.

Website Builds and Pull-Request Previews​

  • The website build strategy has been improved, reducing work and execution time during pull requests.
  • The related GitHub Actions rework is complete.
  • A reported GitHub Pages limitation allows only approximately five to six concurrent pull-request previews. Beyond that, publication can fail. -> Older previews are currently removed manually. A separate issue will track a more sustainable solution.
  • Feedback Preview deployments were positively received as a way to review changes with non-technical stakeholders.

New Repository "wanted"​

  • The proposed contribution from Daniel was deferred because Daniel was absent.
  • Integration into the Tractus-X SDK was discussed as a possible alternative to creating a separate repository. No final integration decision was made.
  • An additional repository was requested for the EDC Management Console application.
  • The established repository-creation approach is to update the shared JSONnet configuration and submit a pull request for review.
  • Repository descriptions, access permissions, and required workflows can be managed through that configuration.

Website Content, AI Agents, and MCP Servers​

  • Website work covers FAQs, audience-specific information, reasons to use Tractus-X, AI agents, and MCP servers. -> A pull request for the AI-related pages is open. FAQ work is still pending.
  • The proposed pages describe available agents, their repositories, capabilities, and skills, as well as MCP servers and the relationship between data spaces and AI.
  • Review needed review the content and submit information about additional MCP servers.

Developer Toolbox and Workflow Documentation​

  • The concrete next step for the testing-automation/toolbox topic remains unclear.
  • Options discussed included formalizing the automation as a reusable workflow, documenting how to use it, or closing the issue if it is purely informational.
  • Missing Developer Hub documentation for existing workflows was identified as a broader problem. -> no assignee yet

EDC Interest Group and Meeting Structure​

  • Creation of the EDC interest group was considered complete. The group had already participated in an EDC meeting last thursday
  • Continued collaboration should use the existing EDC meeting structure.
  • The contributor meeting takes place on Tuesdays at 13:00 and is invitation-based. Interested contributors can request an invitation -> @lgblaumeiser

tractusx-starter-kit​

  • The first open meeting took place on November 12 with @lgblaumeiser and @ReneSchroederLJ.
  • Initial issues have been assigned, and @AndrYurk merged the initial pull request covering Eclipse governance requirements.
  • Open status meetings are intended to continue every two weeks -> see open meetings page
  • Contributors were encouraged to work through the existing issues, create additional issues where needed, and keep the community informed.

Data Space Management Stack and "Portal"​

  • An open Data Space Management Stack meeting was announced for November 13 at 14:00.
  • "Portal" development continues through the new working group, including follow-up work from the hackathon.

Outdated Documentation and Archiving Candidates​

  • Testing documentation, including Jira/Xray-related pages, was identified for review -> no assignee yet
  • Jira is still used for current E2E testing, so removing the documentation without checking current practice would be not benefitial.
  • The product overview and deprecated-component lists need alignment before further cleanup.

Release Management and Timeline​

  • The release-management workshop should represent Tractus-X and its wider ecosystem, including relevant initiatives and industries.
  • Broader participation is required because the outcome also affects the Tractus-X Accelerator and future contribution responsibilities.
  • Stakeholder identification is still in progress. The workshop is tentatively planned after the Community Days, or early next year if necessary.
  • Participants were encouraged to provide release-process feedback through the shared Slido survey.
  • R26.12 was reported to be in testing, with publication planned for December 2.
  • Open Planning for 27.03 is complete; contributors can proceed with the planned development work.
  • An Eclipse Foundation session on security options remains intended for next year. -> Lets talk next year

Secret Scanning and GitHub Actions​

  • Secret scans can take approximately two hours because the current configuration scans excessive history.
  • Scan scope, scheduling, and fetch depth need adjustment, particularly for pull requests.
  • Removing the scanner from a documentation repository was questioned, but no decision to remove it was made.
  • GitHub Actions pinning was reworked across non-archived repositories, with pull requests created for review and merging.
  • Dependabot was reported to detect updates to SHA-pinned sig-infra actions, including actions associated with the main branch.

SSI DIM Wallet​

  • No active maintainer was identified for the ssi-dim-wallet -> The wallet still supports lightweight testing scenarios
  • Announcing the wallet as an archiving candidate through the established process was proposed -> The discussion referenced announcement in the Office Hour and Matrix, followed by an objection period described as approximately two weeks.
  • Archiving is reversible if a user or maintainer later resumes the work -> The exact timing and execution owner were not conclusively established.

AI Contribution Governance and TRG Structure​

  • Placement of AI-related guidance in TRG 7 versus TRG 11 remains under discussion.
  • Copyright and license-header guidance was considered better placed with the existing copyright rules in TRG 7.
  • Any requirements for commit messages or trailers need separate clarification because they are not currently covered in the same way.
  • Existing Eclipse guidance should be reviewed before introducing additional Tractus-X-specific requirements.

  • @stephanbcbauer: Investigate and adjust secret-scanning scope and fetch depth.
  • @stephanbcbauer: Continue preparing the cross-initiative release-management workshop once the stakeholder list is available.

Community Office Hour 2026-11-06

November 6, 2026
Theresa Hilger
Data Space Operations Manager
Stephan Bauer
Eclipse Tractus-X Project Lead

Community Office Hour Meeting Minutes​

Status updates discussed in meeting:

Executive Summary​

  • The current overall Tractus-X release model was questioned. Smaller, independent releases and continuous contributions could reduce coordination effort and delays, while retaining quality assurance and automation.
  • Issue quality, unclear next steps, and missing documented outputs from requester/developer continue to hinder planning and progress.
  • KITS archived, versioned website content has been removed from the GitHub Pages deployment branch to reduce deployment size. Redundant website builds and obsolete content remain under review.
  • The wizard initiative has a repository and initial issues, but still needs governance compliance and active contributors.
  • Security-team synchronization, secret-scanning efficiency, and sustainable funding for maintenance remain unresolved.
  • AI contribution requirements need further review against Eclipse guidance before deciding whether to extend an existing TRG or create a separate one.

Topics Discussed​

Release Process and Workshop Planning​

  • Team questioned whether large, coordinated Tractus-X releases still reflect how the project is used. The original rationale of releasing an integrated whole has weakened as users increasingly adopt individual components.
  • Independent releases (products/services and KITs) could avoid making completed KIT changes wait for a quarterly release window.
  • Continuous contributions, stronger automation, and ongoing quality assurance were discussed as alternatives to the current process.
  • It remains open whether a coordinated release is still needed to capture configurations, compatibility mappings, or variants.
  • The Tractus-X Accelerator's process-analysis work should allow fundamental changes rather than assume that the existing release model must be preserved.
  • Release workshop planned for the next weeks to analyze the current process and possible improvements

KITs and Standards​

  • KITs and standards (Catena-X) serve different levels of detail and do not necessarily require synchronized releases.
  • A fundamental standard change may require a substantial KIT update, while minor changes may have little or no impact on KIT content.
  • Starting with a KIT was discussed as a way to develop and validate approaches before promoting mature content into a standard.
  • DCM, as an example of a mature standard whose Expert Group no longer intends to continue as before. Assumption -> This does not automatically remove the need for occasional KIT maintenance.

Open Planning and Issues​

  • Stephan expects to present 13 Tractus-X Accelerator issues at next week's Open Planning. Outreach to other initiatives has so far produced limited substantive input.
  • Stephan has cleaned up Tractus-X issues, including asking for concrete next steps on long-running topics.
  • Issue (Office hour) descriptions often lack clear use cases, deliverables, or actionable next steps. Collections of links alone do not make the intended work understandable.

Website Deployment Size and Archived Content​

  • Pull-request preview deployments had encountered GitHub Pages size constraints. Stephan reported that deployment content had temporarily exceeded 4 GB.
  • Archived, versioned documentation and (old) KIT content has been removed from the deployment branch.
  • The website now points to release tags and ZIP archives instead of deploying those archived versions as part of the live site.
  • Stephan reported that this should address the immediate deployment-size problem; continued observation was suggested.

Website Actions and Navigation​

  • Website verification, preview deployment, and production deployment perform similar builds, each taking approximately ten minutes.
  • Johann will inspect the Actions and verifier structure for opportunities to remove redundant work and shorten the overall publishing cycle.
  • The website also needs a content and navigation review. The test-management section was cited as potentially obsolete.
  • Stephan has proposed an alternative menu structure and offered to show it in a future demo; no presentation date was agreed.

CX Next AAS-Related Contribution​

  • Daniel Klein is expected to present a proposed contribution from an AAS-related UI tool at the November 13 Office Hour. The exact component scope remains to be clarified.
  • Stephan discouraged creating a separate Tractus-X repository because of governance overhead and ongoing maintenance requirements.
  • Integration into the existing Tractus-X SDK, alongside related libraries and wrappers, was the preferred direction discussed.
  • No final repository placement or acceptance decision was made.

Wizard Initiative​

  • The repository and initial issues are in place, but governance compliance is still outstanding.
  • A first 30-minute weekly session is planned for next Thursday, although it overlaps with the Network Services Committee workshop. How to handle that conflict remains open.
  • Interested contributors need to take ownership of implementation and governance tasks.

Security Team Synchronization​

  • The selected project security contacts do not match the GitHub security-team membership: the GitHub team currently includes all committers.
  • Stephan has already opened an Eclipse help-desk issue about the synchronization problem.
  • Security notifications should reach the designated security contacts rather than all committers. The issue remains unresolved.

TruffleHog and Maintenance Capacity​

  • TruffleHog was reported to perform expensive scans deep into branch and commit history, including during pull requests.
  • Lars recommended checking new changes and the latest main-branch state, including changes that may bypass pull requests, rather than repeatedly scanning unchanged historical commits.
  • A previously resolved false positive in an old commit illustrated the cost of repeated historical scans.
  • A shared Security/DevSecOps or system-team function was suggested for investigating and maintaining this infrastructure.
  • Ownership and funding remain open.

AI Guidance, Commit Requirements, and TRG Placement​

  • The group discussed whether AI-related requirements belong in TRG 7 or a separate TRG 11.
  • Lars cautioned against introducing obligations beyond those required by Eclipse without a clear reason.
  • Commit-message conventions, including sign-off and co-author information, need to be checked against actual Eclipse requirements rather than assumed to be mandatory.
  • A consolidated Tractus-X explanation could improve discoverability, since contributors may not read either the TRGs or Eclipse guidance consistently.
  • The group questioned whether AI disclosure fits release-time checks: unlike license or copyright-header checks, undisclosed AI use cannot reliably be detected during a release review.
  • Lars questioned the legal usefulness of a general AI-assistance declaration when it does not identify which parts of a contribution were generated. No legal conclusion was established.
  • Stephan will review the guidance before the next session. Placement and scope will be discussed with a broader group.
  • Closing the long-running topic before Christmas was expressed as an aim, not an agreed deadline.

Decisions​

  • Decision: Archived, versioned website content will no longer be included in the GitHub Pages deployment branch; release tags and ZIP archives will be referenced instead.

Action Items​

  • @stephanbcbauer: Present the 13 Tractus-X Accelerator issues at next week's Open Planning.
  • @stephanbcbauer: Review the AI-related Eclipse guidance and provide further information before the next Office Hour.
  • Johann Schütz: Review the website Actions and verifier structure and investigate build and deployment optimizations.
  • Unassigned: Finalize a feasible date for the release-process workshop.
  • Unassigned: Evaluate alternatives to coordinated overall releases, including quality assurance, automation, and configuration or compatibility mapping.
  • Unassigned: Review obsolete website content and the navigation structure.
  • Unassigned: Complete the wizard initiative's governance setup and secure contributors for its initial issues.
  • Unassigned: Clarify ownership and funding for shared security and DevSecOps maintenance.
